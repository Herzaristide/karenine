# Widgets (`widgets/`)

The **content** shown in the [panels](#panels). Each widget is a standalone
QML component.

| Widget | Role |
| --- | --- |
| `FileExplorer.qml` | The “Explorer” tab: the computer's folders. Favorites on the left (the home directory, the XDG user directories read from `~/.config/user-dirs.dirs` — documents, downloads, projects, pictures, videos, music, desktop, public, templates, then any other `XDG_<NAME>_DIR` of the file as a plain folder; one favorite per folder, the ones set to the home directory itself skipped; without that file, the usual English or French names that exist — then `/etc/nixos`); in the narrow panel, a row of icon buttons without names, the current one lit, back / forward / up buttons, the path clickable segment by segment, the content as tiles (images as thumbnails) or as a list with size and date, sortable by its column headers; a single footer button cycles through the views (tiles → tree → list → tiles), showing the current one. The path is editable: a click next to the segments, the pencil, Ctrl+L or typing “/” or “~” in the folder turns it into a field that takes an absolute or relative path, `~` and `..` (on a server, relative to its root); the entries of the typed folder are proposed below it, Tab completes (the common prefix, then each proposal, Shift+Tab backwards), ↑ ↓ choose, Enter goes there (a file: its folder, with it selected), an unknown path shakes the bar, Esc cancels. The magnifier (Ctrl+F) turns the bar into a filter of the folder (Enter opens the only match, ↓ goes to the list). “New folder” in the right-click menu creates a folder here: type its name, Enter creates and selects it, Esc cancels. At its foot, the menu shows the properties of what was clicked (or of the folder, clicked in the void): path (a click copies it), type (MIME type, or the number of entries of a folder, a symlink's target), size (a folder's total from `du`, given up after 3 s and never on a mounted server), modification and creation dates, permissions and owner; for a multiple selection, its folder, how many items and their total size. A footer counts the items (or the matches, or the selection and its size). As in a file manager, a click selects and a double click enters a folder or opens a file (`xdg-open`; the panel stays open); a tile can be dragged to another application (Dolphin, browser, messaging…), which receives the file as from a file manager (the panel stays open). Multiple selection: Ctrl+click adds or removes, Shift+click takes a range, a click in the void deselects; dragging a selected tile carries the whole selection; the footer says how many are selected and what they weigh, and clears them; its buttons show hidden files (Ctrl+H), cycle the view, open the folder in the file manager or a terminal. The folder is kept from one tab to another. Above the favorites, a picker switches from this machine to the tailnet's servers (the list from `anna servers list`, those reachable over ssh): the server is mounted with `sshfs` (`host:/`, under `$XDG_RUNTIME_DIR/karenine-sshfs/<name>`, `BatchMode`: an ssh key is required) and stays mounted until switching to another machine; its favorites are its own XDG directories (its `user-dirs.dirs`, read through the mount) and its NixOS config (the root goes through the “/” disk, the path or ↑); the terminal opens an ssh session in the same folder there; no thumbnails remotely. At the top, full width, the disks of each machine (this one included, all from their node_exporter through anna) as `DiskTiles`; a click goes to its main mount point. A failed sample (node_exporter silent) keeps the disks shown and retries 5 s later. |
| `HardwareStats.qml` | The “System” tab: processor, memory and graphics card (the percentage large, the curve behind). At the top, a picker (`MachinePicker`) switches from this machine to a tailnet server: its sample comes from anna (`servers_watch`, over ssh, every 3 s, that server only), graphics card included (NVIDIA through `nvidia-smi`, else AMD through sysfs, the card with the most VRAM; asleep, a card is not read so as not to wake it and the tile says “Asleep”; awake, it is re-read at most every 15 s, to let it go back to sleep); on the right, its name, how long it has been up and its load, or the ssh error, then its actions: terminal (an ssh session in the system terminal), reboot and shut down (two presses; without password-less sudo, the terminal opens to type it); offline, power on with Wake-on-LAN, once its MAC has been recorded online. The machine choice is the same for the Explorer and the System tab (`Widgets.machine`). |
| `ClaudeView.qml`, `ClaudeConversation.qml`, `ClaudeSessionPanes.qml` | The “Claude” tab: the Claude Code sessions (`services/ClaudeSessions.qml`, anna `sessions.rs`), the ones waiting for an answer first, then the working ones, the open ones, and the ended ones grouped by day; a search field, then the projects on one scrolling line (used within the week; temporary folders, the home and a folder holding several projects are left out): a click shows only that project's sessions. Open idle and ended sessions not touched today are hidden until “Show older sessions” or a search. “+” starts a new session in the panel, the terminal button one in a terminal, in the selected project or one to pick; each session also has its terminal button. A panel session's pending permission or question can be answered on its card in the list (`ClaudeAsk.qml`). A click opens the conversation in place of the list (`services/ClaudeChat.qml`, anna `transcript.rs` and `drive.rs`), as in Claude Desktop: the requests, Claude's text and thinking (folded), each tool call as a line that unfolds into its command and output, the diff of an edit, or the input and output of an MCP tool, subagents indented; “Load earlier” goes back a page. Tabs under the header switch from the conversation to the session's panes (`ClaudeSessionPanes`, anna `summary.rs`, read from the whole transcript and its `subagents/*.meta.json`): **Context** — how full the context window is (the last request's input tokens against the model's window, as `claude` reports it when driven), the model, the connectors and tools called, the files read; **Changes** — every file edited or created with its +/− lines, a click unfolds its whole diff; **Outputs** — what the session produced to look at or reuse (anna `outputs.rs`): the files written while it was active in `~/lens`, `~/mesh` and `~/tune/<project>`, the media and office documents named by its commands and connectors, the documents it created with `Write`, the artifacts it published (source code stays in Changes); a click opens one, the folder icon its folder; **Tasks** — Claude's task list (`TaskCreate`/`TaskUpdate`, `TodoWrite`), then its subagents, background commands and reporting tasks with their state (running ones pulse), what a subagent did (tool calls, tokens, time) and reported, a background command's output; “Open the subagent” shows a subagent's own conversation (read only), the back arrow returns to the session. Typing “/” lists the slash commands (arrows, Tab, Enter): `/clear`, `/usage`, `/context`, `/model`, `/effort`, `/permissions`, `/plan`, `/resume`, `/exit` and `/help` are done by the panel, the others — `/compact`, the skills, the project's own — by Claude Code, whose list anna asks per folder (`claude_commands`); a local command's answer shows in the conversation. Writing resumes the session: anna runs its own `claude` on it in stream-json (`--resume`), in the folder's direnv (`direnv export json`; a `.envrc` that isn't allowed is never allowed by anna: `claude` starts without it and the header says so), with Remote Control on when Claude Code's `remoteControlAtStartup` is — the header's button (or `/remote-control`) turns it off or on, the arrow opens the session on claude.ai, and a session under Remote Control is not stopped for being idle —; the text shows as it is written, Escape or the stop button interrupts the turn, holding Space dictates (Enter sends), links show in the accent color (`MarkdownText.qml`), chips set the permission mode, the run's cost shows in the header. The permissions and questions Claude asks open as cards (`PromptHost`), wherever you are. A session open in a terminal is read live; “Take over” ends its terminal's `claude` (refused while it works) so it can be driven from the panel; the terminal icon still brings an open session's terminal to the front, or resumes an ended one in a terminal. |
| `PhoneWidget.qml` | The phone linked through KDE Connect (anna, `phone.rs`), a wide, low card at the bottom of the “System” tab (`HardwareStats.qml`), whatever machine is picked there; `telephone` opens that tab. Its card: state, mobile network, battery; “Screen” shows it in a scrcpy window, ring, clipboard. Its notifications reach the notifications bell, sent by `kdeconnectd` like any other. Accepts or declines a pairing request. Its state and actions live in `services/Phone.qml`, shared with the bottom bar. |
| `PhonePop.qml` | The phone's actions in the bottom bar, above its button (next to the computer's battery, showing the phone's battery while it is connected). A narrow column that comes out of the bar like the other flyouts (`Lip`, same hollowed corners and ink), with no title: only the bar's buttons — screen, ring, clipboard — rising into it one after the other, and going back down in reverse order as the column sinks into the bar. A success turns the icon into a check for a moment; an error, a pairing key or what to do without a phone is written above them (the column widens for it). A pairing request offers ✓ / ✕. |
| `BarPill.qml`, `BarIcon.qml` | The motion shared by every bottom-bar button (`BarButton`, workspaces, phone, battery, clock): the hover fill blooms from the centre, the accent fill opens with a slight overshoot, a press squeezes the content and a spring releases it, a click leaves a short flash; icons change by cross-fading. |
| `NotificationCenter.qml` | The notifications, unfolded under the bell of the top bar (`TopIsland`, which shows their count; `widget:notifications` opens it too): the desktop notifications not closed yet, newest first (`services/Notifications.qml`, the shell being the `org.freedesktop.Notifications` server). Nothing pops up over the screen. Each one (`NotificationCard.qml`): icon or image, application, time, title, text, its actions, an inline reply field when the application offers one; a click runs its default action, ✕ or a right click closes it. “Clear all” closes them all. |
| `NotesWidget.qml` | The “Notes” tab: a Keep-like wall of cards (`anna notes …`, `notes.rs`: `~/.local/share/anna/notes/notes.json` and one file per image). The notes stay on this machine. A note is written in the bar: type it, then pick “Create a note” among the results (`services/NoteSource.qml`, which also lists the matching notes; picking one opens the tab). At the top of the tab, “Paste”; Ctrl+V on the wall turns the clipboard into a note: an image (a screenshot, an image copied from a browser), an image file copied from a file manager, or text. Every screenshot also lands there by itself: the daemon watches `/tmp/screenshot-*.png` (Print keys, search, pilot) and `<Pictures>/capture-*.png` (the top bar), and the tab reloads when `notes.json` changes. The cards, in columns that scroll, pinned ones first then the most recent: a click edits the text (an image's caption; Escape or a click elsewhere saves, emptying a text note deletes it), a double click opens an image; on hover, at the top right (icons `pin`, `copy`, `terminal`, `trash`), pin, copy back to the clipboard, open in Claude Code (`claude` in the system terminal, from the home directory, the note as its first message — an image by its path), delete. |
| `CalendarWidget.qml` | The “Calendar” tab: the calendars and tasks of the Google account (`services/Agenda.qml`, `anna agenda <from> <to>`, `anna tasks`), in four modes switched in the header (remembered in `Widgets.agendaView`): Day, 3 days and Week, columns with the hours as rows, each event placed at its time and length (overlapping ones share the column), all-day events and dated tasks (Google keeps their day only) in a band above, a red line at the current time; and Tasks, the whole list (`TaskList`). The hours scroll over the whole day: twelve of them fill the height, 8:00 to 20:00 when the tab opens (an hour keeps at least 28 px on a very low panel), and the hour at the top stays put when the panel is resized; an event hidden above or below shows as a “▴ 1” / “▾ 2” chip at the edge of its column, which scrolls to it. Everything is created and edited there (`AgendaEditor.qml`): + opens a new event at the next full hour (in Tasks mode, focuses the new-task field), a click in an empty slot creates an event there, in the band a task that day; dragging an event moves it by quarter hours and across days, its bottom edge changes its end; dragging a task or an all-day event changes its day. A task sent by the bar's tasks drawer (`Widgets.showTasks`) opens in the editor. The tab re-reads every five minutes while shown. Without an account, it offers to connect one. |
| `TaskList.qml`, `TaskCheck.qml` | The Google tasks, in the bottom bar's tasks drawer (`compact`: a header with “Open calendar”, the field takes the keyboard) and in the Calendar tab's Tasks mode: every list or one picked in chips; a field where Enter creates a task — no date, today or tomorrow, in the list shown or the one of its button — and stays ready for the next (shown at once, greyed until Google answers); then overdue (red), today, upcoming and undated tasks, subtasks indented under their parent, the done ones folded at the end. The box (`TaskCheck`) checks a task off in Google; a click on a task opens it in the Calendar tab's editor. A Claude button (the sparkles of the panel's Claude tab; also “Claude Code” in the editor) opens a terminal on a Claude Code session whose first request is the task's title and notes (`Agenda.openInClaude`), in the `~/code` folder named like the task's list (case ignored), otherwise in the home folder. The bar button's badge counts the tasks due today or overdue (`Agenda.dueCount`, tasks re-read every five minutes while an account is connected). |
| `GoogleAccount.qml` | The Google account, in the settings and in the Calendar tab while none is connected. Google only opens its APIs to an app declared there: first the OAuth client the user created once (a “Desktop app” in the Google Cloud console, Calendar and Tasks APIs enabled), its ID and secret, or the path of the JSON downloaded from the console; then “Sign in with Google”, which opens Google's consent page in the browser (anna receives a token, never the password); then the address and “Disconnect” (the token is revoked at Google). State through `services/Google.qml` (`anna google …`). |
| `GlassButton.qml` | The widgets' button, flat like the bar (a quiet fill, the accent color if `accent`). |
| `MachinePicker.qml` | The machine choice, shared by the Explorer and the System tab: a chip named after the machine shown, which unrolls it and the tailnet servers reachable over ssh (`anna servers list`), online or not. The choice goes into `Widgets.machine`, the same for every tab; each one follows it (the Explorer mounts the server with sshfs when it comes back on screen, and goes back to the mounted machine if mounting fails). |
| `FocusRing.qml` | The outline of what has the keyboard, shared by all controls. |
| `MusicPlayerWidget.qml` | Music player. |
| `Tuner.qml` | Tuner — see [Music tools](#audio-tools). |
| `Metronome.qml` | Metronome — see [Music tools](#audio-tools). |
| `Harmony.qml` | What plays, as harmony: chord, key on the circle of fifths — see [Music tools](#audio-tools). |
| `MiniGraph.qml` | Small reusable graph. |
| `Settings.qml` | The panel's “Settings” tab, a single column of sections (`SettingsSection`, each a card of `SettingsRow`s): **appearance** (theme, dark or light, as a `Segmented` choice; the accent colour, from `Theme.presets` or any hue on a slider, sent to anna on release; reset), **voice** (the wake word “Karénine” through `Pilot.voiceWakeToggle()`, a `SettingsSwitch`; the voice language), **screen**, **interface language**, **video** (`DeviceSettings`), **assistant** (`AssistantSettings`), **Tailscale** (the node on or off with a `SettingsSwitch`, the logged-in account and online peers, “Log in”, which opens Tailscale's authorization page in the browser, or “Disconnect”; through `services/Tailscale.qml`), **disks** (`DiskHealth`), **account** (`GoogleAccount`). Sound and Wi-Fi are set in their bottom-bar flyouts. |
| `SettingsSection.qml`, `SettingsRow.qml`, `SettingsSwitch.qml`, `Segmented.qml` | The settings' building blocks: a titled card; a row (icon, title, subtitle, a control on the right, or a check when it is the chosen one); a switch; a choice between a few options with a sliding pill, like the panel's tabs. |
| `DiskTiles.qml` | The disks as a treemap, the same in the Explorer (every machine, its name above its block) and in the system tab's machine cards (that machine's): one block per machine, cut into its disks. A disk's area follows the square root of its capacity, never under 35 % of the row's biggest one's weight, so the big disk stays clearly the biggest and a USB key keeps a readable tile; blocks share the width by their disks. Machines sit side by side while each disk keeps 96 px, otherwise they wrap; a machine too wide alone gets a taller block where its disks stack. Blocks are whole: disks are separated by a thin line, only the block's outer corners are rounded. Each tile fills from the left as far as it is full, a flat fill closed by a thin line (red from 90 %). The type as an icon (NVMe, SSD, HDD, USB) and the name in small capitals top left, preceded by a dot when SMART says to keep an eye on it (orange) or that it is failing (red, red outline); used / total at the bottom, and on hover the percentage, temperature and wear; the percentage in large figures in a tall tile. Top right, a small house and the user's initial per home directory on that disk (the one you are in, in accent; on hover the bottom line shows its path), and the eject button of a removable disk of this machine (or Ctrl+E on the focused tile): through `services/Disks.qml`, its filesystems are unmounted, a LUKS container locked, then the disk powered off with `udisksctl`; a file still open on it makes the eject fail with udisks' error. A click opens it in the Explorer, on its machine (mounted if needed); the current one is outlined in accent, the tiles of a machine being mounted breathe. Each refresh updates the tiles in place (`KeyedModel`): hover and focus stay, the fill glides to its new level, tiles glide to a new layout. `Disks.fromDrives` turns anna's drives into the tiles' shape. |
| `KeyedModel.qml` | A list of keys for a `Repeater`, updated in place (`sync(keys, apply)`): what disappeared is removed, what arrives inserted, the rest moved, so the delegates that stay are not recreated — hover, focus, animations and state survive a refresh; they read their data by key from a separate map. Used by `DiskTiles` and the system tab's machine cards. |
| `DiskHealth.qml` | This machine's disks in the settings (`servers_watch` narrowed to it): model, type, main mount, space, and SMART health from smartctl_exporter (wear, temperature, hours on) as a pill: healthy, keep an eye on it (wear ≥ 80 % or above 70 °C), failing (SMART failed), unknown (no SMART). A click shows the disk in the Explorer. When no fixed disk has SMART, it says why and gives the command that grants NVMe access without rebooting. |
| `DeviceSettings.qml` | The webcam in the settings, shown only when there is one: the default one (PipeWire nodes, `wpctl set-default`) and ‹ › to change it. |
| `WifiSettings.qml` | In the bottom bar's Wi-Fi flyout, and in the touch bar's Wi-Fi menu (`TabletBar`): the Wi-Fi radio on or off, the current network, and the visible networks (the eight strongest) to join, through NetworkManager (`nmcli`). A known network is joined in one click; an unknown protected one asks for its password in the row itself. Without a wireless interface, the section does not appear. Below it, a Tailscale card: the tailnet, this node's name and address, and a button to turn it on or off (or to log in when it is not). |
| `BluetoothMenu.qml` | The Bluetooth menu, unfolded under its button in the top bar (`TopIsland`), and next to the touch bar (`TabletBar`). At the top, the adapter switch; then the devices: connected first, then paired, then the ones being discovered (the adapter scans while the menu is open, and stops when it closes). A click on a device: connected, it disconnects; paired, it connects; new, it pairs, becomes trusted (it will reconnect by itself) and connects. A connected headset with a microphone offers two modes: **Music** (A2DP, high-quality sound, no mic) and **Call** (HFP, the mic, phone-quality sound) — classic Bluetooth cannot do both at once. The modes are the PipeWire card profiles (`pactl list cards`). The headset only changes mode through this choice: WirePlumber's automatic switch is turned off in the NixOS configuration (`modules/audio.nix`), since anna's wake word listens all the time and the headset kept flipping. |
| `GestureControls.qml` | Webcam gesture control (anna): on/off, the engine's state and the camera to use. A floating card (`camera`), see [Panels](#panels). |
| `NotificationCard.qml` | One notification of `NotificationCenter`. |
| `NixIcon.qml` | A monochrome SVG icon tinted to the theme: the artwork ships white and is recolored, so one file serves light and dark. |

## Keyboard

Every widget action is reachable without the mouse. The outline in the bar's
tint (`FocusRing.qml`) shows what has the keyboard; a click does not make it
appear.

| Key | Effect |
| --- | --- |
| ↑ (empty field) | Opens the widgets; a second time, moves to the tabs. |
| ↑ ↓ (launcher open) | Browse the launcher's results by relevance, grid and rows alike (↑ enters through the best one; ↓ from it goes back to the field). Enter opens the chosen suggestion; ← → adjust the chosen volume or accent. |
| Arrows, Enter, Backspace (in the Explorer) | Move the cursor in the folder, open the file or enter the folder (Enter on several selected: opens them all), go up to the parent. Shift+arrows extend the selection, Space adds or removes, Ctrl+A takes everything, Esc clears the selection. Typing the first letters of a name jumps there; “/” or “~” starts typing a path (Ctrl+L or F6 from anywhere in the tab), Ctrl+F filters. Alt+← / Alt+→ and the mouse's side buttons go back and forward in the history, Alt+↑ goes up. |
| ↓ (in the field) | Closes the widgets. |
| Tab / Shift+Tab | Move from one control to the next: widget, tabs, field. |
| Enter / Space | Press the button, the tile or the chip. |
| Shift+Enter | On the screenshot: the whole screen (like right click). |
| ← → / ↑ ↓ | Adjust sliders (volume, brightness), the track position (±5 s), the tempo, the A, the color pickers, the voice language (Shift: bigger step). |
| ← → | Change widget: from the empty field, the tabs, or any control that does nothing else with them. Ctrl+Tab too (Ctrl+Shift+Tab: backwards). |
| Esc | Gives the keyboard back to the field; in the field, drops the chosen suggestion, then closes the widgets, then the bar. |

The power menu of the top bar locks, suspends and logs out on the first
press; reboot and shut down ask for a second one. The floating card (gesture control) takes the keyboard once clicked; Esc closes
it.
